## 2026-09-22 用户主导的投影重构（最终形态，36 离线测试过）

演进链：ProjectionPolicy 三字段 → 删 default_model → 删整个 policy 对象 → 删 repair 旋钮 → system_prompt 参数也删 → **prompt 变更作为事实落盘**。

最终形态：
- `build_context(traj)` **无参数**：system prompt 全从轨迹来——初始值在 header（store.start 记原文），变更以 `prompt_change` entry 追加，覆盖式提取、路径上最后一次生效、无变更回落 header。f(trajectory) 纯函数更强："同一份轨迹文件，两次投影逐字节相同"。
- `Agent.attach(traj)` 发现轨迹记录的 prompt 与 self.system_prompt 不一致（首次没记 / resume 换模板）→ 追加 prompt_change（幂等）。用户点破的洞："resume 换模板后新 prompt 没落盘"。
- repair 旋钮撤掉：悬挂调用补自描述占位是投影内置默认行为；drop 档（pi 的做法）书中作备选记录，代码不外露——没有真实需求不加旋钮。
- 纪律：5a 不预立空配置对象；5b 压缩策略进来、字段多到需要版本号时再立对象，那时版本号才是 eval 坐标。

prompt_change 是对 pi 的偏离（第 10 种类型，pi 的 prompt 在 harness 不落盘）：本项目要审计，就得是事实。

pi 实现核实（2026-09-22 网上查证 pi-mono，CSDN session 格式解析 + 官方文档）：system prompt 由 SYSTEM.md / APPEND_SYSTEM.md / AGENTS.md 定制、启动时从磁盘组装，session 文件（header + entry 类型 message/model_change/thinking_level_change/compaction/branch_summary/label/leaf/session_info/custom_message/custom）里**无任何 prompt 记录**，buildSessionContext 只返回 {messages, thinkingLevel, model}；resume 后静默用当前文件内容。pi 自己不对称：model_change 落盘、prompt 不落盘。另：pi 有独立 leaf entry 持久化 leaf 指针（我们是隐式最后一条）；compaction 带 tokensBefore；版本 version=3。
- 两种划线的取舍（已写进 05a 机制一）：划的是"回放一致性的责任"——pi 交给环境（同一 checkout 才可比，也不记权重版本），我们收进事实层（prompt 记录成本低、变更少、是行为最大单一输入）。一致性是记录成本与收益的权衡，不存在"记全"。
