## books/python/agent-loop.md：补 message 与轨迹的 JSON 定义
- 原稿只写了 `{'role':'', content:''}` 和一层 step 数组，都补成了完整定义。
- message：定为**内部统一表示**（id / role / content 支持 string 或 part 数组 / name / tool_calls / tool_call_id / reasoning / created_at / usage / meta），出去再写 provider adapter。明确 role 五个值、`function.arguments` 是 JSON 字符串、tool 消息必须带 tool_call_id、思考块带签名不可改。
- 轨迹：核心立论是**轨迹 ≠ messages 存档，是超集**；改成 `events` append-only 扁平事件流作唯一真相源，turn/step/messages 为派生视图。顶层含 `env`（model / system_prompt_sha / tools schema_sha / code_version，为评测与 RSI 可复现）。event 通用字段 seq / type / turn_id / step_id / parent_id / actor / message / payload；payload 列了 model_response、tool_call、tool_result（output_raw 与 output_sent 双份）、interrupt、compaction、memory_extracted。
- 关联：字段与《从 Messages 到 Agent Loop》第一节四家对照表衔接，文中直接指过去了。

### 修订（用户打回后）
- 用户批评：message 定义 req/resp 混在一起、usage/meta/latency 是 response 级字段不该进 message，整体像 trace 不像 message。批评成立。
- 改法：message 改为**按 role 分四种形态**（system/developer、user、assistant、tool），各给各的 JSON；开头先讲清 message 属于请求体、response 里的 message 段才是一条 message，finish_reason/usage/耗时归 response。
- tool_result 两套表达（OpenAI 独立 role=tool vs Anthropic user content 里的 tool_result 块）明确"选一套、别同时留两种"。
- 为自洽：message 不再自带 id，轨迹里一律用 event `seq` 定位；`compaction.replaced_message_ids` 改成 `replaced_events`（seq 区间）；`model_response` 示例改为 message 与 payload（response 级字段）分列。
- 语气：清掉对话腔（"这里有个必须先掰清楚的事""不是装饰"等），改成文档叙述。
