## dsh agent-loop 循环结构分析（opensource-refs/deepseek-harness）
- 主循环文件：`packages/core/agent-loop/src/agent.ts`，类 `ReactLoopAgent`。三层嵌套：kick()（`while (await this.turn())`，inbox 有 pending 就开下一轮）→ turn()（while(true) 逐 step，completed/max-tokens 且 next-step 空才退出；preStep 认领消息+组装上下文+`agent/pre-step` waterfall 可改写/reject）→ step()（while(true)：调 LLM→有 tool-call 就 executeToolCalls→结果塞回 next-step inbox 再调，直到模型不调工具；max-tokens 粘性）。
- inbox 双队列（`packages/core/agent/src/inbox.ts`）：next-turn / next-step；claim 先认领全部 next-step 再取一条 next-turn；followup→next-turn、steer/inject→next-step（inject 不唤醒）。
- 上下文管理（首次回答漏掉，用户追问补全）：①`agent-loop/src/runtime-context.ts` 每步把动态上下文渲染成 plugin user/message 投影进请求（有变才发，被 compaction replace 后失效）；②真正的 context 压缩在独立包 `packages/compaction/*`（非 agent-loop 包内），两处事件接缝：`agent/pre-step`（tokenMeter 压力超 thresholdRatio 触发）+ `agent/request-error`（CONTEXT_WINDOW_EXCEEDED 时压缩后返回 retry）；③spill 包：超大工具输出落盘、上下文只放路径（挂 tools/post-execute）；④guard 包：重复工具提醒 + 超时。循环可插拔接缝全是 Cordis waterfall/serial 事件，印证 everything is a plugin。

## 事件接缝全清单（用户追问补齐，已核对源码）
- waterfall（可拦截改写）：agent/pre-step、agent/request、agent/request-error、tools/pre-execute、tools/execute、tools/post-execute、tools/code-dispatch-log。
- serial（排队不可改写）：仅 agent/turn-stopping（只在"已有结束原因且 next-step 空"时触发，aborted/error 不经过）。
- emit（通知）：agent/created、agent/session-start、agent/status、agent/error、agent/disposed、agent/inbox/inserted|discarded|claimed、agent-loop/config-start-failed、tools/result、tools/change。
- session 日志事件（session.append 落库 + session/event 订阅，只能看不能拦）：turn/start、turn/end、step/start、step/end、user/message、assistant/chunk、assistant/message、tool/call、tool/result、request/header、request/context、agent/inbox/spliced、todo/write、compaction/start|summary|end|prune。
