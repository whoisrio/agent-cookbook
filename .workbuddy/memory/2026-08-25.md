## dsh agent-loop 循环结构分析（opensource-refs/deepseek-harness）
- 主循环文件：`packages/core/agent-loop/src/agent.ts`，类 `ReactLoopAgent`。三层嵌套：kick()（`while (await this.turn())`，inbox 有 pending 就开下一轮）→ turn()（while(true) 逐 step，completed/max-tokens 且 next-step 空才退出；preStep 认领消息+组装上下文+`agent/pre-step` waterfall 可改写/reject）→ step()（while(true)：调 LLM→有 tool-call 就 executeToolCalls→结果塞回 next-step inbox 再调，直到模型不调工具；max-tokens 粘性）。
- inbox 双队列（`packages/core/agent/src/inbox.ts`）：next-turn / next-step；claim 先认领全部 next-step 再取一条 next-turn；followup→next-turn、steer/inject→next-step（inject 不唤醒）。
- 上下文管理（首次回答漏掉，用户追问补全）：①`agent-loop/src/runtime-context.ts` 每步把动态上下文渲染成 plugin user/message 投影进请求（有变才发，被 compaction replace 后失效）；②真正的 context 压缩在独立包 `packages/compaction/*`（非 agent-loop 包内），两处事件接缝：`agent/pre-step`（tokenMeter 压力超 thresholdRatio 触发）+ `agent/request-error`（CONTEXT_WINDOW_EXCEEDED 时压缩后返回 retry）；③spill 包：超大工具输出落盘、上下文只放路径（挂 tools/post-execute）；④guard 包：重复工具提醒 + 超时。循环可插拔接缝全是 Cordis waterfall/serial 事件，印证 everything is a plugin。

## dsh tools 安全与可靠性默认设计（已核对源码）
- 核心内置（dsh-tools / agent-loop）：四阶段执行链 tools/pre-execute（allow/deny/ask，无审批服务降级 deny）→ tools/execute（around 包装链+工具体）→ tools/result（emit 通知，观察者异常只记日志）→ tools/post-execute（accept/block，block 把纠正反馈变 error 结果）；pre-execute 后还有 ToolGuard 单调守卫（只能否决不能放行，listener 顺序无法把拒绝变回允许）。
- 任何环节抛错都转结构化 ToolExecutionResult（isError + error.message + error.info{name,code}）回给模型，错误不穿透循环；parseArguments 非法 JSON 保留为文本、空输入映射 {}。
- 调度（tool-calls.ts）：executionMode parallel（滚动池，默认 maxParallelToolCalls=10）/ exclusive（屏障）；dispatch 可重叠但 policy/results/context 按模型序提交（commitReady 只提交连续前缀槽位）；工具可声明 concludesTurn 直接结束本轮。
- 取消语义（可靠性核心）："取消从不抛弃已开始的工具体"——started promise 达 quiescence 才标 ABORTED；未开始调用记合成错误 TOOL_ABORTED_BEFORE_DISPATCH，保证 replay 每 tool/call 有对应 tool/result；dispatchToolBody 把 callerSignal 与 wrapperSignal fuse；调度器内部失败停止新派发、排空已开始、抛第一个失败不伪造结果。
- 可选插件：timeout-policy（合作式超时：工具声明 timeoutMs+承诺响应 exec.signal，deadline 换 signal，超时替换为结构化 TOOL_TIMEOUT，code 作用域区分内外层 deadline）；repeat-tool-reminder（不否决只 enrich 模型上下文）；spill（超大结果落盘换路径）；compaction-tool-result-pruner（修剪工具结果）。
- 结论：dsh 无 agent eval 体系（BENCHMARK.md 仅操作指南、ui-trajectory 仅展示、evaluator.ts 是代码求值器）；自建 eval 可用 session 事件流当轨迹。

## 重试/重复调用/工具结果消息的精确语义（用户追问，已核对源码）
- LLM 请求层重试默认：`llm/llm/src/retry-policy.ts` DEFAULT_MAX_RETRIES=2（normal 模式，首次请求外最多重试 2 次），retryableCodes 默认 5 个（EMPTY_RESPONSE/RATE_LIMIT/SERVER/TIMEOUT/TRANSPORT），backoff 默认 initial 500ms / max 10s / jitter 0.1（指数退避+抖动）；另有 always 模式无限重试。执行在 llm-retry 包（agent/request-error 决策 + llm/retry、llm/retry-started 日志事件）。
- **工具调用失败无自动重试**——失败即失败，作为 tool result 回模型，由模型决定下一步（易混淆点）。
- repeat-tool-reminder（guard 包）：默认 thresholds=[3,5,8] 连续重复触发提醒；**有参数相同判断**——chain key=[toolName, canonicalize(args)]，canonicalize 深度 key 排序（属性顺序不同也算相同）；**只提醒不拦截**（never veto），提醒是 createUserMessage（source.kind='plugin', form='notice'）走 additionalContexts→next-step inbox；用户消息插入（source user）即重置链；deny 的调用也计数。
- 工具结果消息：createToolResultMessage = createUserMessage 包一层，source={kind:'tool',callId}，content=[{type:'tool-result',toolCallId,content,isError}]——即 role=user、来源 tool，走 tool/result 事件落 surface；重复提醒才是 plugin 来源的 user message。两条路径别混。

## compaction 的 log vs surface 机制（用户追问，已核对源码）
- **不是分岔**：session log append-only 永不改写，压缩只在尾部追加 compaction/start → compaction/summary → 带 surfaceOp {op:'replace',start,end} 的 user/message → compaction/end 四个事件。
- 两层模型：日志（events，真相源）+ 表面（surface，日志投影=发给 LLM 的消息列表，deriveMessages 从 surface 派生）；replace 事件把 [start,end] 旧节点从表面遮蔽换摘要，log 不变、surface 变。
- 默认策略（compaction-basic config.ts）：thresholdRatio=0.8（占用 80% 触发）、retainRatio=0.16（保留尾部 floor(contextWindow×0.16) tokens，可换 retainTokens 绝对数）、maxTokens=8192、compactionRetries=1、maxOverflowRetries=1、auto=true。
- 区域选择（region.ts selectCompactableRange）：尾部往回累计 token 到预算=保留尾，从头部到 cutoff 全压（压头部非中间）；toolPairingBalancedBefore/After 保证不拆 assistant 的 tool-call/result 对。
- 一致性：summarize 异步期间 surface 变化抛 SurfaceChangedError 作废；compaction/start-end 配对成事务锁，失败记 error 版 end 不留孤儿锁；摘要必须比被压内容小（token 校验）；总结是真实 LLM 调用（重建 system+tools+前缀复用 KV 缓存），compaction/summary 记 provider/model/usage/rawOutput 可重建。
