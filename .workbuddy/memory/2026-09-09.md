- 设计定型（与 09-08 讨论一致但更简）：每 session 一个 asyncio.Queue 收件箱 +
  常驻 worker（首次消息 spawn，永不自行退出，stop() 显式取消）——"消息进队但
  task 死了"竞态在设计层面不存在；消费端分类：step 边界 drain=steering（拼进
  当前上下文），worker 空闲取到=followup（新 turn）；一步的 turn 无 step 边界，
  插话自然降级 followup，无需特判。turn_end 从"只写 log"升级为总线真事件
  （stage02 的 UI/测试要等它）。
- 测试基建：FakeLLM 加 first_call_gate（把"消息在 step 在飞时到达"做成确定性
  时序）和 first_call_tool（把 turn 撑成两步，steering 才有 step 边界可用）；
  Harness 的 turn_end 用 Queue 缓存不用 Event——多 worker 并发收尾时 Event 的
  set/clear 会互相吃掉信号（真踩到）。
- 真实 LLM 实测（qwen3.7-flash）：三连问 demo 完美命中——插话 9.97s 发出，
  18.5s step 边界被 drain，模型自发 search("会议室 预订") 并同轮答两问；
  log 里 steering 行 ts=9.97 但按消费顺序排在 18.5 之后，"到达时刻≠消费时刻"
  是正文的教学点。API 慢（一步 8.5s）反而成了"steering 等待真实发生"的证据。
